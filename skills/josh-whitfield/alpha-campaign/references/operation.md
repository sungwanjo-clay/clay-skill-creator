# Scoring and execution details

The parent is a native manual batch workflow. It owns ICP compilation, optional explicit
review memory, discovery, independent research/audit, Radar scoring, per-person native
Audience ingestion and queue reconciliation. The Audience-triggered helper owns email finding,
email verification, the full Alpha Copy graph and final Audience writeback.
Neither graph sends messages or enrolls records.

Radar retains the original four dimensions: fit, proof, insight, usefulness. Rubrics and
weights depend on the audience and actual offer. Weighted geometric scoring uses verified
source evidence, freshness decay, contradiction penalties and source-removal sensitivity.
Qualification requires its own score floors, identity check, at least two verified sources,
substantive primary evidence and no disqualifier. These are heuristics.

For each review category, explicit binary feedback updates a Beta(1,1) prior. The ranking
bonus is 8 × (posterior mean − 0.5), bounded within ±4 points. No human feedback means
zero bonus. It cannot change the evidence score or qualification verdict. Feedback IDs
are deduplicated; replacing a person's rating removes the old contribution first.
Memory is scoped to the exact normalized audience/offer brief and Radar settings. Supply
it explicitly from the prior native parent output; it does not fetch past runs by itself.

Copy retains independent evidence, commercial relevance, offer fit, timing and specificity
strengths, weighted 30/25/20/15/10. Every strength must be at least 2/4 and the geometric
score at least 65 by default. Factual checks apply independently. A separate critique and
one revision precede final assembly of greeting, observation, tentative implication, actual
offer, exact CTA and signature. Source and provider names are retained in evidence receipts,
not injected into the email text.

The Finder output is not enough. Verification requires success=true, an exact returned
address match, status=valid, no adverse sub_status, and free_email=false. Missing values
fail closed. ZeroBounce onlySafe=true prevents its normal catch-all-as-valid conversion;
Python additionally checks the returned fields. No address pattern is generated by a model.

Each source task returns at most ten candidates; the number of tasks is ceil(max_people/10).
Python keeps at most the requested 1–100 distinct people, one per employer. It does not
backfill rejected or unverifiable candidates. Only Radar-qualified people consume email
provider calls and only verified people reach Copy. A fully eligible 100-person batch
can be expensive and slow; start with a small authorized test.

The Audience bridge requires a verified personal LinkedIn URL. Source profile URLs that
cannot satisfy this identity lookup remain held; URLs are never fabricated. Parent queue
receipts identify exact record IDs. A completed parent proves ingestion, not completed copy.

Helper terminal branches save results in owned fields and replace QUEUED with the actual
verdict. Hard action errors remain visible in native runs and require reconciliation. Do not
silently count unresolved queued records as held or ready. Existing primary email is preserved.
Owned output fields are cleared on a new queue operation so old drafts cannot masquerade as new.

The default installation remains draft. Process a bounded exact-record batch with the runner,
or publish the dedicated helper when automatic execution is authorized. Keep one active batch
per person. The Audience action does not offer an atomic batch/version comparison; editing a
queued record or concurrent batches can race. Native source execution can deduplicate unchanged
record inputs, and some draft installations only stage test data. An acknowledgment alone
does not prove a new run started. If no new run appears, use the native Test data panel
to run only the exact queued rows; never rerun completed samples blindly. Read the run IDs
and final record values, and inspect errors before any retry.
